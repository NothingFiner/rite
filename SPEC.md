# Roadmap 5.11 — Thesaurus

A writer selects one word the way they already do (caret in the word, or the
word selected), right-clicks, and gets a **one-item menu**: *Thesaurus…*.
Choosing it opens a **popover** anchored at the click point that shows the
word's WordNet senses, each with its synonyms and (where WordNet has them) its
antonyms. The writer marks one synonym, presses **OK**, and the word in the
document is replaced — keeping its leading capital and trailing punctuation.
Dismissing the popover any other way is a **no-op**, always.

## Context (decisions the implementer needs)

**The dataset is a brotli-compressed flat WordNet, committed to the repo.**
`src-tauri/assets/thesaurus.tsv.br` (2.57 MB, 11.83 MB uncompressed) holds
139,857 sense rows over 85,169 single-word headwords from English WordNet 2020
(`ewn:2020`). It is generated by `scripts/build-thesaurus.py`, which is run by
hand and needs `pip install wn brotli` plus a one-time data download. Nothing
downloads at build or run time; the app is offline. `src-tauri/assets/WORDNET-attribution.txt`
carries the CC BY 4.0 attribution and must ship beside the asset.

**Row format** — one row per *sense*, tab-separated, no header:

```
lemma  pos  sense-number  gloss  synonyms  antonyms
```

`pos` is WordNet's raw code (n, v, a, s, r); `gloss` is the synset definition
truncated to 120 characters; `synonyms` and `antonyms` are comma-separated
lemmas and may be empty. Rows are the unit of sense grouping because WordNet
puts antonyms on the **sense**, not the word: "light" as an adjective has
antonym "heavy", "light" as illumination does not. Multi-word lemmas were
excluded at generation time — the menu only ever takes over for a single word.

**Selective takeover is the whole point of the menu rule.** The webview's own
right-click menu is valuable: Copy works on a phrase selection, and with
continuous spell checking on, WKWebView offers Learn / Ignore / Unlearn
Spelling on a squiggled word. The app must take that menu away **only** for a
single word — collapsed caret inside one word, or exactly one word selected.
Everything else keeps the native menu. This is deliberate, not an oversight.

The listener is on `document` but the takeover must be limited to the editor
sheet (`.editor-sheet`): a right-click on a chapter title in the navigation
drawer, or in the assistant panel, is not a thesaurus request and must keep its
native menu. No sentence drives that distinction directly; it is a constraint
on the implementation, and the unit fixture puts the sheet's class on the
element it right-clicks.

**Nothing is applied by hovering or by a single click.** Clicking a synonym
only marks it; text changes only on OK. Any other dismissal — Cancel, Escape,
click outside — leaves the document byte-identical. This is the user's rule:
"otherwise the whole operation should be a no-op".

**Word shape is preserved on apply.** WordNet lemmas are mostly lowercase and
carry no punctuation, so replacing "Happy," with "glad" verbatim would damage
the sentence. The document word is split into leading non-letters, the core
word and trailing non-letters; the replacement inherits the original's leading
capitalisation and trailing punctuation.

**Applying is a normal edit.** The replacement goes into the editor sheet, is
read back through the existing `syncSection` path (the same road typing takes),
marks the document modified, and is undoable. No special history entry.

**Commands.** The Rust side exposes:

- `show_word_menu(x, y)` — builds the one-item native menu and pops it at the
  window coordinates of the click. It emits nothing itself.
- `thesaurus_lookup(word)` — `Result<Option<WordEntry>, String>`; `null` means
  "not in WordNet", an error means the query itself was unusable.

The existing `menu` window event is the authority for activation: Rust's
`menu_event()` must recognise the thesaurus id even though the id is not in the
static File/Edit menus. `useMenu`'s id→action map gains the thesaurus action;
existing callers of `createMenuActions` build deps without a thesaurus, so keep
the map lazy (an arrow) so the dep is only touched when the action runs.

**Rust seams the tests drive** (`src-tauri/src/thesaurus.rs`, exported from
`lib.rs`):

```rust
pub struct Sense {
    pub part_of_speech: String,   // "noun" | "verb" | "adjective" | "adverb"
    pub sense_number: u32,
    pub gloss: String,
    pub synonyms: Vec<String>,
    pub antonyms: Vec<String>,
}
pub struct WordEntry { pub word: String, pub senses: Vec<Sense> }

impl Thesaurus {
    pub fn lookup(&self, word: &str) -> Option<&WordEntry>;
    pub fn headword_count(&self) -> usize;
}
pub fn parse_dataset(tsv: &str) -> Thesaurus;
pub fn bundled() -> &'static Thesaurus;   // decodes include_bytes!("../assets/thesaurus.tsv.br") once
```

`Sense` and `WordEntry` are `serde::Serialize` with `#[serde(rename_all = "camelCase")]`,
so the webview reads `partOfSpeech` / `senseNumber` while Rust keeps
`part_of_speech` / `sense_number`. `Thesaurus` must be usable without a Tauri
runtime so `cargo test` can drive it.

**Menu seam** (`src-tauri/src/menu.rs`):

```rust
pub const THESAURUS_ITEM_ID: &str = "thesaurus";
pub fn word_menu_definition() -> Vec<MenuNode>;  // exactly one Item, label "Thesaurus…"
```

`menu_event()` returns `Some(MenuEvent { name: MENU_EVENT_NAME, id: "thesaurus" })`
for `THESAURUS_ITEM_ID` and `None` for anything else, unchanged.

**Frontend seams.**

`src/composables/useThesaurus.js`:

```js
export function takeOverWord(selectionText, wordAtPoint) // string | null
export function wordAtOffset(text, offset)                // { word, start, end } | null
export function splitAffixes(word)                        // { prefix, core, suffix }
export function shapeReplacement(replacement, affixes)    // string
export function useThesaurus()                            // state + install, below
```

`useThesaurus()` installs a document-level `contextmenu` listener for the host
component's lifetime and returns:

- `state` — `{ open, word, senses, loading, error, x, y }` (reactive).
- `openCurrent()` — called by the `thesaurus` menu event; opens the popover for
  the word captured at right-click and runs the lookup.
- `apply(replacement)` — writes the replacement into the document and closes.
- `close()` — closes without touching the document.

`state.word` is the document word **including its punctuation** ("Happy,"):
that is what the popover displays and what the replacement is shaped from. The
lookup query is `splitAffixes(state.word).core`, because WordNet has "Happy",
not "Happy,". The composable captures the character run under the pointer and
extends it over adjacent punctuation (never whitespace) so the slice can be
shaped; `wordAtOffset` itself reports only the word's letters.

`src/components/ThesaurusPopover.vue` — props `visible`, `word`, `senses`,
`loading`, `error`, `x`, `y`; emits `apply` (final replacement string) and
`cancel`. Escape and a click outside are document-level listeners installed
while the popover is visible, so they work without the popover having focus.
Markup contract the tests query (class names matter):

| element | meaning |
|---|---|
| `.thesaurus-popover` | root; `position: fixed` with `left` / `top` from `x` / `y` |
| `.thesaurus-word` | the document word as it appeared |
| `.thesaurus-sense` | one per sense, in dataset order |
| `.thesaurus-pos` / `.thesaurus-gloss` | that sense's part of speech / gloss |
| `button.thesaurus-synonym` | one per synonym; `aria-pressed="true"` when marked |
| `.thesaurus-antonyms` | "Antonyms" label + lemmas; absent when the sense has none |
| `.thesaurus-empty` | "No synonyms found" |
| `.thesaurus-error` | the error line |
| `.thesaurus-loading` | the loading state |
| `button.thesaurus-ok` / `button.thesaurus-cancel` | OK (disabled until marked) / Cancel |

`App.vue` mounts the popover once and installs the composable; the editor
component itself is untouched (the listener is on `document`).

## Sentences

### Rust — dataset and lookup

- **S-001** (rust): it should decode the bundled brotli dataset at first use and index at least 80,000 single-word headwords.
- **S-002** (rust): it should find a word regardless of the query's case — "The" finds the entry for "the".
- **S-003** (rust): it should return one group per sense, each carrying its part of speech, sense number and gloss.
- **S-004** (rust): it should name parts of speech as noun, verb, adjective or adverb, with satellite adjectives ("s") reported as adjective.
- **S-005** (rust): it should list a sense's synonyms without repeating the headword itself.
- **S-006** (rust): it should list a sense's antonyms when it has any and an empty list when it has none.
- **S-007** (rust): it should answer an unknown word with "no entry" rather than an error.
- **S-008** (rust): it should reject an empty or whitespace-only query with an error naming the query as invalid.
- **S-009** (rust): it should skip a malformed dataset row and still load every well-formed row around it.
- **S-010** (rust): it should ship the dataset's attribution (English WordNet 2020, CC BY 4.0) as a file next to the bundled asset.

### Rust — the one-item word menu

- **S-011** (rust): it should describe the word menu as exactly one app-owned item, id `thesaurus`, label "Thesaurus…".
- **S-012** (rust): it should route the `thesaurus` id through the existing `menu_event` authority onto the `menu` window event.
- **S-013** (rust): it should leave the static application menu without any thesaurus item — the File and Edit id sets are unchanged.

### Unit — takeover decision

- **S-014** (unit): a right-click with a collapsed caret inside a word should take over for that word.
- **S-015** (unit): a right-click on a selection that is exactly one word should take over for that word.
- **S-016** (unit): a right-click on a multi-word selection should not take over, so the webview's own menu (copy, spellcheck Learn/Ignore) survives.
- **S-017** (unit): a right-click where there is no word — whitespace, or an empty block — should not take over.
- **S-018** (unit): when it takes over it should prevent the browser's default context menu and ask Rust to show the word menu at the click point.

### Unit — keeping the writer's word shape

- **S-019** (unit): it should split the document word into leading non-letters, the core word, and trailing non-letters — "Happy," gives "", "Happy", ",".
- **S-020** (unit): a replacement should keep the original's leading capitalisation — "Happy," + "glad" gives "Glad,".
- **S-021** (unit): a replacement should keep the original's trailing punctuation — "word." + "term" gives "term.".

### Unit — the popover

- **S-022** (unit): it should show the original word and one group per sense with part of speech and gloss, positioned at the click point.
- **S-023** (unit): it should list each sense's synonyms, and show antonyms in a labelled line only for senses that have them.
- **S-024** (unit): its OK button should stay disabled until exactly one synonym is marked.
- **S-025** (unit): marking a second synonym should move the mark, leaving only one marked.
- **S-026** (unit): pressing OK should emit `apply` with the marked synonym shaped to the original word.
- **S-027** (unit): cancel, Escape and a click outside should close it without emitting `apply`.
- **S-028** (unit): with no senses it should show "No synonyms found" and no OK button.
- **S-029** (unit): a failed lookup should show the error line and keep the popover open.
- **S-030** (unit): a lookup in flight should show a loading state with no sense groups.

### E2E

- **S-031** (e2e): right-clicking a single word should invoke the word-menu command with the pointer position and leave the document text unchanged.
- **S-032** (e2e): right-clicking a multi-word selection should send no word-menu command.
- **S-033** (e2e): the `thesaurus` menu event should open the popover with the sense groups returned by the lookup command.
- **S-034** (e2e): marking a synonym and pressing OK should replace the word in the document with capitalisation and punctuation preserved, and mark the document modified.
- **S-035** (e2e): Escape should close the popover and leave the document unchanged.

## Expected red state before implementation

The Rust module compiles with `todo!()` bodies, so every dataset sentence fails
as a panic, not a build error. `word_menu_definition()` returns an empty vector
and `menu_event` ignores the thesaurus id, so the menu sentences fail on their
assertions. The Vue stubs (an empty popover template, a composable whose
handlers do nothing) keep the app mounting cleanly, so the unit and e2e
sentences fail on their assertions and every pre-existing test still passes.
